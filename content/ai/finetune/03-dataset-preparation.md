"garbage in, garbage out" 在微调上会被进一步放大：数据质量决定了效果上限，训练技巧只能逼近这个上限。本文按流程整理数据准备的纪律：**定格式 → 造/收数据 → 清洗过滤 → 切分**。

## 第一步：定义目标与格式

先写一句可测量的目标："让模型按我们的客服话术回复退款类问题"。目标含糊，后面全是返工。再定数据格式，**对齐推理时的真实形态**：

```jsonl title="sft-format.jsonl"
{"messages": [
  {"role": "system", "content": "你是格致知识库助手，回答须引用资料编号。"},
  {"role": "user", "content": "向量检索和 BM25 有什么区别？"},
  {"role": "assistant", "content": "两者机制不同 [1]：向量检索……"}
]}
```

三条原则：

- **system prompt 与线上部署时完全一致**，训练时没有的指令，模型推理时不会"自动懂"
- **assistant 的回答就是"标准答案"**，它应该是你真正希望模型产出的样子（含引用格式、长度、语气），不是"大概这样吧"
- 一个样本只教一件事；多样的任务宁可拆成多条

## 第二步：数据的三个来源

1. **真实日志改造**：线上真实 query + 人工改写的理想回答，最贴近分布，优先级最高
2. **强模型蒸馏**：用 GPT-4o 级模型按 few-shot 生成候选答案，人工审改。量大，但**必须人审**（蒸馏会连强模型的坏习惯一起带过来）
3. **人工直写**：核心场景（拒答话术、关键流程）手写，少而精，是"行为锚点"

数量参考（SFT 行为微调）：几百条能见效，1k~10k 常见区间；**质量 > 数量**，1k 条精修常胜过 10k 条噪音。各类别的比例要反映真实分布且保护小类（重要但少见的场景专门补样本，防被多数类淹没）。

## 第三步：清洗与过滤（机器 + 人）

```python title="clean-pipeline.py"
rules = [
    lambda x: len(x["messages"][-1]["content"]) > 20,      # 太短的不是合格回答
    lambda x: "作为AI" not in x["messages"][-1]["content"], # 蒸馏腔过滤
    lambda x: x["messages"][1]["content"] not in seen_queries,  # 去重
]
data = [d for d in raw if all(r(d) for r in rules)]
```

人工抽查是机器规则的校准器：随机抽 5% 逐条读，发现新的坏模式就补一条过滤规则。常见坏模式：回答与问题无关（弱相关对）、蒸馏腔（"作为一个AI"）、信息过时、格式不一致、敏感内容。

**推荐再加一道"模型过滤"**：让强模型给每条样本打分（相关性/正确性/格式合规），低于阈值的进人工复核——用[评测同款的 LLM-as-judge 思路](../evaluation/03-agent-evals.md)。

## 第四步：切分与留痕

- **train / val 切分**（如 95/5），val 不参与训练只做早停与过拟合监控
- 切分按**任务类别分层**，保证 val 覆盖每个场景
- 数据版本化：数据集和代码一样进 git（或 DVC），每次训练记录"哪个版本的数据 + 超参 + 评测分数"。没有留痕，实验之间无法归因

最后一个反直觉提醒：**先用最笨的基线（few-shot prompt）跑分**（见[评测先行](../evaluation/01-evaluation-first.md)），如果微调后的模型在 val 上不如精心设计的 prompt 基线，说明数据还不够好，先回去修数据，而不是调超参。
