这篇是训练侧唯一的一篇全景文：不求会训，只求**看到一个模型行为时，能定位它是哪个阶段造成的**。三个阶段一句话概括：预训练给它知识，SFT 教它说话，RLHF 矫正它的脾气。

## 阶段一：预训练——海量文本的" next token 预测"

任务简单到荒谬：给定前文，预测下一个 token，在数万亿 token 上重复。模型从中学到语法、事实知识、代码、推理模式——**所有"聪明"都在这个阶段出现**。

- 输入：清洗后的全网语料（网页、书籍、代码）
- 产物：基座模型（base model）——一个"续写机器"
- 关键认知：base model **不是助手**。问它"法国的首都是哪里"，它可能续写"这是一道常见的历史考题"——因为在训练语料里，这句话后面更常跟这个

## 阶段二：SFT（监督微调）——把续写机器变成助手

用人工写的高质量"指令→回答"对（几万到几百万条）继续训练，模型学会**以助手的口吻响应指令**：该回答就回答、该拒绝就拒绝、该用格式就用格式。

- 指令跟随能力、对话结构、"你是 XX 助手"的人设，都在这层
- 这一层的典型产物怪癖：过度礼貌、爱列条目、爱说"作为一个 AI"——因为它见过大量这样的示范数据

## 阶段三：偏好对齐（RLHF / DPO）——矫正脾气

SFT 教会"怎么答"，对齐阶段教会"怎么答得更好"。流程（RLHF 经典版）：

1. 让模型对一个 prompt 生成多个回答
2. 人类标注员排序：哪个更有用、更无害
3. 用排序数据训练一个奖励模型（reward model），再用 RL（PPO）让主模型去最大化这个奖励

**DPO**（Direct Preference Optimization）是更简的替代：跳过奖励模型，直接用偏好对微调，工程上更稳，近年开源模型多用它或其变体。

这层的产物：更安全的拒绝、更符合人类偏好的措辞——以及两个著名副作用：**奉承（sycophancy）**（用户暗示什么就顺着说）和**拒绝过敏**（对无害请求也过度谨慎）。遇到模型"立场软"，根源在这里。

## 应用工程师的推论

1. **知识截止在预训练**：模型不知道训练截止后的事——这是 RAG 存在的根本理由（见 [RAG 章](../rag/01-chunking-strategies.md)），也是"过时 API 用法"幻觉的来源
2. **微调改行为不改知识**：SFT/LoRA（见[微调章](../finetune/01-lora-and-qlora.md)）能教会格式、风格、流程，很难"灌进"新事实——新知识走 RAG，不走微调
3. **temperature 调不掉的毛病是训练的锅**：过度道歉、列表癖，换 prompt 措辞或换模型比调参数有效
4. **奖励作弊是本质风险**：模型优化的是奖励模型眼中的"好答案"，不是真正的好答案——评测（见[评测先行](../evaluation/01-evaluation-first.md)）必须独立于任何单一信号源
