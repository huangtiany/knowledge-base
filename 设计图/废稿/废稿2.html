从零理解 Attention 与 Transformer 投影矩阵

发表于 2026-08-28 · 约 3200 字 · 阅读时间 12 分钟 · LLM基础 RAG

在阅读复杂的自然语言处理论文或长上下文工程实现时，注意力机制（Attention）往往被赋予许多神秘的数学色彩。但如果从软件工程师“键值索引”的直觉出发，Attention 的本质就是一次连续的、带权重的查表过程。

一句话直觉：Query 是“我想查什么”，Key 是“各位置的索引标签”，Value 是“实际存的内容”。匹配发生在 Q 与 K 之间，取出的则是 V 的加权组合。

§ 1 Q、K、V 三个投影矩阵的作用

每个 token 的初始向量（Embedding）进入注意力层后，会分别与三个参数矩阵 $W^Q$、$W^K$、$W^V$ 相乘，得到三种用途截然不同的向量副本：

1. Query (Q)：当前位置在向整句话发问时持有的搜索关键词向量；
2. Key (K)：当前位置可被其他人检索的标签线索；
3. Value (V)：当前位置真正包含并准备向下游传递的信息特征。

Attention(Q, K, V) = softmax ( Q KT / √dk ) V

§ 2 缩放因子为什么必须是 √dk

当向量维度 $d_k$ 很大时，点积结果的方差也会随之增大。如果不加限制直接送入 softmax，较大的数值会使输出迅速推向饱和区，导致反向传播时的梯度趋近于零（梯度消失）。除以 $\sqrt{d_k}$，正是通过尺度缩放将点积方差重新拉回为 1。

scaled_dot_product_attention.py Python 3.11 
import numpy as np

def softmax(x):
    e = np.exp(x - np.max(x, axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def scaled_attention(Q, K, V):
    # 获取键向量的维度 dk
    d_k = Q.shape[-1]
    # 矩阵乘法点积后除以根号 dk 保持方差稳定
    scores = (Q @ K.T) / np.sqrt(d_k)
    weights = softmax(scores)
    return weights @ V

# 模拟 4 个 token，每个 token 向量维度为 64
Q, K, V = [np.random.randn(4, 64) for _ in range(3)]
output = scaled_attention(Q, K, V)
print("Output tensor shape:", output.shape)  # (4, 64)

§ 3 多头机制与工程架构

单头注意力只能关注一种语法或语义关系。多头注意力（Multi-Head Attention）通过将输入切分成 $h$ 个低维子空间分别计算，令各个头专注于不同的语意线索（例如一个头关注主谓宾搭配，另一个头关注代词指代链）。

§ 4 与全栈开发中线程/并发设计的触类旁通

在全栈工程实践中，高并发下虚拟线程或协程的设计，同样遵循类似的解耦原则：以最小的代价分配任务上下文，避免在阻塞等待上浪费物理资源。

VirtualThreadConcurrencyDemo.java Java 21 
public class VirtualThreadConcurrencyDemo {
    public static void main(String[] args) throws Exception {
        // 使用虚拟线程执行器并行发起向量索引批量请求
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            IntStream.range(0, 100).forEach(i -> executor.submit(() -> {
                // 模拟轻量级非阻塞调用
                Thread.sleep(Duration.ofMillis(50));
                System.out.println("Indexed batch: " + i);
                return i;
            }));
        }
    }
}
